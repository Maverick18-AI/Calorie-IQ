# CalorieIQ 2.2 development release

Version: **2.2.0-dev.1**, generation **2**. Built on the published
`1a323b20069cd921628362008dc821b1ba9135c0` checkpoint. The commit containing this
document is the release commit; Git identifies it without a circular SHA entry here.

## Completed scope

### Phase A — Diary and mobile experience

- Orange/blue/navy light and dark themes, matching manifest and locally generated
  SVG/PNG Home Screen icons. No external fonts or new dependencies.
- Six icon-and-text navigation destinations, mobile bottom navigation, safe areas,
  keyboard skip link, visible focus, reduced-motion support and large controls.
- Daily remaining/eaten/goal calories, progress percentage and macro target percentages.
- All four meal groups, including empty states, meal calorie subtotals and direct Add.
- Edit, duplicate, move and delete with the existing revision-checked Undo.
- Previous/next/today/calendar controls and copying from any selected day.
- Quick-add calories with optional macros; blank macros remain unknown.
- Recent/frequent/favorite/custom/saved/recipe shortcuts and library filters.
- Local favorites persist through saved-food edits. Logged snapshots are unchanged.
- Less prominent serving metadata and optional nutrients use disclosure panels;
  nutrition basis, main macros, quantity and Add remain directly available.

### Phase B — Nutrition and goals

- Tracks calories, protein, carbohydrates, fat, saturated fat, fiber, total sugars,
  sodium, cholesterol and potassium. Values remain per declared base quantity.
- Uses OFF `_serving` / `_100g` standard values. Sodium/cholesterol/potassium are
  converted from OFF standard grams to app milligrams once. Label-entry fields use
  the displayed app units. No missing values are fabricated.
- Calories/macros lead basis selection. A lone micronutrient per serving cannot
  displace otherwise usable per-100 macro data. Bases are not mixed to fill gaps.
- Recipes and saved meals carry nutrient snapshots; fractional portions scale all
  nutrients. Imported recipe claims are checked against their ingredient snapshots.
- Daily and trailing-seven-day nutrition totals, configured target progress, and
  macro energy shares based on 4/4/9 kcal per gram. Missing macro values suppress
  percentages. Incomplete totals are explicitly marked as known subtotals.
- Optional nutrient targets and existing date-specific overrides.
- Optional goal weight, direction, weekly change preference in kg and activity.
- Optional adult maintenance estimate using Mifflin–St Jeor. Resting kcal/day:
  `10 × kg + 6.25 × cm − 5 × age + coefficient` (male +5, female −161).
  Activity factors 1.2/1.375/1.55/1.725 are approximate assumptions; they are not
  validated personalized activity measurements. No loss/gain adjustment is imposed.
  Estimate inputs are not added to diary backups. Choosing Use fills a goal form;
  a separate Save goals action applies it. Weight logs never alter calorie goals.
- Whole-package action uses explicit compatible package mass/volume or stated
  serving count. Conflicting, missing, ambiguous, untyped or unsupported quantities
  disable the action. No density, cup-weight or multipack-count guesses.
  Changing manufacturer serving metadata invalidates retained package conversion.

### Phase C — Weight and polish

- Start/current/goal/change/remaining summaries and start-to-goal progress.
- Responsive 7/30/90-day plots, exact editable records and optional trailing
  seven-calendar-day averages. Averages use real samples only, not invented days.
- kg/lb entry and goal-unit conversion preserve physical weight.
- Future-dated weigh-ins remain editable but do not become current weight or appear
  in the window ending today. No arrival-date or weight-loss predictions.
- Goals, libraries, recipes, weights and diaries remain isolated by local profile.

## Development storage and compatibility

The version-2 database key/schema, revision checks, full-string conflict checks,
Web Lock, restore validation, recovery snapshot and profile architecture remain.
Extra nutrients, favorites, package metadata and profile planning preferences are
optional extensions. Older four-nutrient backups validate; absent nutrients are
unknown. Legacy version-1 migration remains covered by existing tests, without
additional migration work. Restoring a richer 2.2 backup into an older app is not
recommended because older interfaces cannot expose its extra fields.

As explicitly requested, this **development** build clears CalorieIQ-owned test
local/session storage once at generation 2 initialization. It does not clear
unrelated keys, downloaded backups or files on the PC. New entries survive ordinary
reopens of the same build. `development:false` retains the production persistence
path. The banner stays visible. New modules are included in the coherent offline
shell cache.

## Known limitations and deferred work

- Real iPhone 16 / Safari / Home Screen / VoiceOver / camera acceptance remains
  pending. Desktop Edge checks are not physical iPhone verification. WebKit is not
  installed in this environment; no browser software was installed for this task.
- OFF records can be wrong. The known Ritz records are not corrected upstream;
  verify the package, correct locally and save the barcode override. Whole-package
  availability depends on trustworthy metadata. No food-specific constants were added.
- CGI search service availability/rate limits remain outside this static app's
  control. Barcode lookup, saved foods and manual entry are alternatives.
- No arbitrary vitamins, custom meal-group names, exercise/water tracking, cloud
  sync or authenticated family accounts were added. These are future options.
- Calorie estimation is a rough adult maintenance calculation; preferences do not
  constitute a personalized diet prescription. Users retain manual goal control.
- Weekly summaries show known totals against seven configured daily targets;
  unlogged days are called out, not treated as actual zero-intake days.
- Local profiles are organizational separation, not private accounts. Backups are
  unencrypted and include all profiles. Browser eviction/device loss still needs
  external backups. Only one tab may edit at once.
- Apple may retain an older installed Home Screen icon until it refreshes the
  installation metadata. Do not clear site data just to refresh an icon.

## Physical iPhone 16 acceptance checklist

1. Open the existing HTTPS site in Safari, then the installed Home Screen app.
   Confirm 2.2.0-dev.1 and the orange/blue interface. Confirm one development reset;
   add an entry, close/reopen, and ensure it stays.
2. Check portrait/landscape, light/dark, enlarged text, bottom safe areas, VoiceOver
   headings/labels, keyboard focus and date/number controls.
3. Allow/deny camera permission; scan UPC/EAN in varied lighting. Stop/restart,
   background/return and verify the camera indicator stops. Test photo decoding and
   supported zoom/torch. Record any problematic barcode and lighting conditions.
4. Compare actual labels: one 130-kcal/26-g pack, two packs (260), half pack (65),
   grams and a liquid measured in ml. Verify extra nutrients and unknown vs zero.
   Use whole package only when the shown package quantity matches the label.
5. Correct an inaccurate barcode, save it, rescan and verify the saved correction.
   Try name search and note any service errors separately from barcode recognition.
6. Exercise meal moves/Undo/date copy, recent/frequent/favorites, recipe portions,
   saved meals, weekly nutrition and date-specific targets.
7. Log/edit/delete weights, switch kg/lb before saving, select 7/30/90 days and the
   average. Confirm goals do not change when logging weight. Switch profiles.
8. Export to Files, restore that test backup and inspect totals; try an invalid
   file. Test offline reopening and manual/saved-food logging after initial caching.
